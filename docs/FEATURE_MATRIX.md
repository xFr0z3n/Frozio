# FEATURE_MATRIX — spoti.pw (+ taurus) → Frozio on NaviMus 1.6.1

Generated by `work/scripts/gen_matrix.py` from `work/recon/spotipw_features.md` (spoti.pw 0.22.0, 239 rows) and `work/recon/taurus_features.md` (taurus 0.60.5, taurus-only rows only).

**Read before using this matrix:**
- **Gating:** spoti.pw's *public source* has no licence or paywall gate. Per the user (Phase 0 Q3), the released spoti.pw builds gate **Visualizer, Workshop (shaders), AutoMix and Web Player**; those rows are marked `gated = yes`. Visualizer and AutoMix are implemented in taurus; Workshop and Web Player have no source anywhere and wait on a description. Frozio ships everything ungated.
- **Scope decisions (Phase 0):** redesign look only, so native-look rows are `out of scope`; F60 lossless/Soulseek is dropped. Code reuse comes from GPL-3.0 sources (taurus, spoti.pw ≤ v0.21.1, amperfy); Frozio is GPL-3.0.
- **Hook points** name types and selectors verified in `work/dumps/` (see `docs/CLASSES.md` for the OBJC / SWIFT-CLS / SWIFT-VAL legend). NaviMus's Swift functions are **symbol-stripped**, so for SWIFT-CLS and SWIFT-VAL targets only the *type* is verified. The concrete entry point (vtable slot / witness-table entry) gets resolved per feature in Phase 2. OBJC selectors and system APIs are verified as-is.
- **Feasibility/effort/risk** are per-area estimates for Phase 0 planning; each feature PR re-evaluates them.
- Rows marked `needs decision` are not planned until you decide.

**Totals:** 280 rows (239 spoti.pw + 36 taurus-only): partial: 91, N/A: 79, out of scope (native look): 72, yes: 35, needs description: 2, dropped: 1
